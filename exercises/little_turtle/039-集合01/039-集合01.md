### 6.如果存在多个列表，需要筛出这些列表中相同的元素，可以使用什么方法？

- ~~`zip`~~

- 将它们转换为集合，然后进行交集运算，得出的结果便是它们之间共同拥有的元素

- 代码

  ```python
  >>> # 方法一
  >>> l1 = [1, 2, 3, 4, 5]
  >>> l2 = [1, 3, 5, 7, 9]
  >>> l3 = [1, 1, 2, 3, 5]
  >>> set(l1).intersection(l2, l3)
  {1, 3, 5}
  >>> # 方法二 运算符 & 求交集
  >>> set(l1) & set(l2) & set(l3)
  {1, 3, 5}
  ```

### 0.想办法优化源代码，使得程序的执行效率提高 10000 倍以上

- 源代码

  ```python
  import random
  import timeit
  
  haystack = [random.randint(1, 10000000) for i in range(10000000)]
  needles = [random.randint(1, 1000) for i in range(1000)]
  
  # 请在此处添加一行代码，使得查找过程的执行效率提高 10000 倍以上。
  
  def find():
      found = 0
      for each in needles:
          if each in haystack:
              found += 1
  
      print(f"一共找到{found}个匹配。")
  # 这好像是之前的测试代码时长的模块
  t = timeit.timeit("find()", setup="from __main__ import find", number=1)
  print(f"查找过程一共消耗{t}秒。")
  
  ```

- 小甲鱼

  ```python
  import random
  import timeit
      
  haystack = [random.randint(1, 10000000) for i in range(10000000)]
  needles = [random.randint(1, 1000) for i in range(1000)]
  
  # 请在此处添加一行代码，使得查找过程的执行效率提高 10000 倍以上。
  haystack = set(haystack)  # 将列表转化为集合
      
  def find():
      found = 0
      for each in needles:
          if each in haystack:
              found += 1
      
      print(f"一共找到{found}个匹配。")
      
  t = timeit.timeit("find()", setup="from __main__ import find", number=1)
  print(f"查找过程一共消耗{t}秒。")
  ```

- 说明-小甲鱼

  ```python
  解析：为什么列表变成集合之后，效率竟然提高了这么多呢？
  
  其实是因为集合的背后是有散列表的支持，而列表则没有！
  
  所以，列表的每次查找都需要从头到尾地扫描，而集合则只需要简单地查表操作。
  
  打个比方，这就好比你在新华字典里面查找一个 “龟” 字，in 在列表上的查找方法是从头翻到尾，挨个对比是不是 “龟” 字；而 in 在集合上的查找方式是通过笔画的索引，直接就拿到了这个 “龟” 字所在的页码。
  ```
